Section 04
Local-First Memory Architecture

No full conversations stored permanently. A lightweight summarized profile grows over time — like a child's learning journal, not a surveillance log.

Storage Option Comparison

❌ localStorage — Rejected

5MB limit, synchronous (blocks UI), no structured queries, easily cleared by the browser, no versioning or migrations. Completely unsuitable.

⚠️ SQLite (WASM) — Overkill

~3MB WASM download, complex setup, requires Origin Private Filesystem API (fragmented browser support), overkill for this use case.

✅ IndexedDB + Dexie.js — Winner

Built into every browser, 50MB+ quota, async non-blocking, structured data, versioned migrations, TypeScript-first, zero bundle cost.

5 Memory Layers

1

Child Profile (permanent)

Name, age, mascot, preferred languages. Written once during onboarding.

2

Interest Tags (auto-updated)

Weighted topics: { tigers: 9, birds: 6, space: 3 }. Decays 0.1/day. Max 10.

3

Session Summaries (7-day rolling)

Gemini writes a 2-sentence summary per session. Only 7 kept; old ones auto-deleted.

4

Learned Objects (max 200, LRU)

Object name + translations + emoji. Used for "You already know tiger!" moments.

5

Vocabulary Cache (per language)

Word → translation pairs cached locally. Grows as child explores. Works offline.

Section 07
Camera Mode Architecture

Child points camera at any object — Leo identifies, teaches, translates, and quizzes. Photos are never stored. Privacy by design.

🔐

Privacy by Design

Frame captured as base64 → camera stream released before the network call → sent to Gemini → image buffer discarded. No image ever written to disk, IndexedDB, or Drive. A consent explainer is shown on first use (remembered per-child in localStorage), and a 4 MB payload guard blocks oversized captures.

💰

Cost Model

Gemini Flash Vision ≈ $0.0001 per scan. 10 camera uses per day = $0.001/day = ~$0.03/month. Parent's key, parent's usage — effectively negligible for any typical child session.

Camera Implementation

Session Summary — Auto-Triggered (Child Never Ends Manually)

How session end is detected: A 5-year-old will never consciously "end" a session — they'll just put the phone down, switch apps, or walk away. The app detects session end automatically using four browser events, whichever fires first:
  • visibilitychange → document.hidden === true — child switches app or locks phone
  • pagehide — PWA moved to background on iOS/Android
  • beforeunload — browser tab or window closes
  • Inactivity timer — 90 seconds of no speech or taps → summary triggered silently

All four events call the same triggerSessionSummary() function, which is debounced so it only runs once per session. If the child resumes within 5 minutes, the session continues and no summary is written yet.

Topics explored this session: {topicList}
Duration: {durationMinutes} minutes

Write a memory summary in JSON. Be warm and specific:
{
 "summary": "2 sentence warm summary of what was explored",
 "newInterests": ["tigers", "teeth", "Kannada"],
 "topicsToRevisit": ["how tigers hunt"],
 "emotionalNote": "Very excited about animal facts"
}

This is stored locally and used for tomorrow's personalised greeting.
Keep summary under 200 characters. Only return valid JSON.

No Adult Topics

Input blocklist + system prompt prevents violence, adult content, political controversies, and harmful subjects.

Short Answers Only

Max 3 sentences enforced via prompt. Children cannot be led down complex or harmful rabbit holes.

No Internet Browsing

Leo cannot browse URLs or access real-time web content. All knowledge from Gemini's trained model only.

Minimal Data to AI

Only first name and age sent to Gemini. No location, no photos stored, no persistent conversation logs.

Parent PIN Lock ✓ Built

An optional 4-digit PIN (SHA-256 hashed → parentPinHash) gates Settings & the Dashboard via a tablet-friendly keypad. Set/remove it in Settings; unlock is remembered per visit.

Encouraging Tone Only

Leo never says "Wrong!" All deflections are warm: "Interesting idea! Let's explore this instead..."

Camera Consent Flow

Every camera session shows a plain-language consent dialog. No background recording ever.

Offline Safe Mode

Without connectivity, Leo uses cached content. Children never see error screens — Leo explains warmly.

API Key Security — Google Sub as Encryption Factor

Encryption model change: The Gemini key is no longer encrypted with a 4-digit PIN (10,000 brute-force attempts = milliseconds). Instead, the AES-GCM key is derived from the user's Google sub — the stable, globally unique ID in their ID token. This ties decryptability directly to possessing a valid Google session. Security = as strong as the user's Google account (typically 2FA).
1

Onboarding: child name + age → Gemini key

After Google Sign-In, Leo asks the child's name (large input) and age (4 / 5 / 6) — age feeds age-appropriate AI responses — then a parent enters their Gemini API key. Every step has a Back button; no PIN required here.

2

Validate, then encrypt with sub-derived key

The key is verified live against Google's models endpoint before saving — an invalid key is rejected on the spot, not hours later. Then PBKDF2(sub + APP_SALT, 100k iterations) → AES-GCM key; ciphertext stored in IndexedDB and synced to Drive. Raw key never persisted.

3

New device: auto-restore from Drive

Sign in with Google → sub extracted from fresh ID token → key derived → ciphertext fetched from Drive → decrypted in-memory. Zero friction for the parent.

4

PIN is a child-mode lock only ✓ Built

The optional 4-digit PIN's only job is to block children from tapping into parent settings — it has no role in key encryption or recovery. Setup + keypad gate now ship.

5

Runtime: decrypt → use → wipe

API call needed → derive key from cached sub → decrypt → call Gemini → wipe plaintext key from memory. Never held longer than one request cycle.

6

Returning visit: one-tap "Welcome back"

Because sub lives in memory only (never persisted), a page refresh loses it. The profile reloads from IndexedDB, then a friendly "Welcome back, {name}! Tap to continue" screen recovers the session with a single Google token tap — re-deriving the key. No re-onboarding, no data loss.

☁️ Google Drive Sync — Default for All Signed-In Users

When a parent signs in with Google, Drive sync is enabled automatically — no extra toggle or opt-in required. The child's name is captured during the very first sign-in screen and tied to the Google account. This unlocks multi-device restore and lays the groundwork for future multi-child profiles.

Key insight — drive.appdata scope: The app requests the https://www.googleapis.com/auth/drive.appdata OAuth scope. This creates a hidden app-private folder in the parent's Google Drive that is invisible in the Drive UI but fully backed up by Google. No storage quota impact for typical usage. Completely free. No server infrastructure needed — calls go directly from the browser to the Google Drive REST API.

// Derive AES-GCM key from Google sub — runs in WebCrypto, never leaves browser const deriveKeyFromSub = async (sub: string) => { const APP_SALT = 'curiouskie-v1' // public constant, not secret const encoder = new TextEncoder() const keyMaterial = await crypto.subtle.importKey( 'raw', encoder.encode(sub), 'PBKDF2', false, ['deriveKey'] ) return crypto.subtle.deriveKey( { name: 'PBKDF2', salt: encoder.encode(APP_SALT), iterations: 100_000, hash: 'SHA-256' }, keyMaterial, { name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt'] ) } // On new device: sub from fresh Google token → derive key → decrypt from Drive const restoreApiKey = async (sub: string, ciphertext: string) => { const aesKey = await deriveKeyFromSub(sub) const { iv, data } = parseCiphertext(ciphertext) const plaintext = await crypto.subtle.decrypt({ name: 'AES-GCM', iv }, aesKey, data) return new TextDecoder().decode(plaintext) // ← Gemini key, used once then discarded }
